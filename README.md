# Hangyodon Life

このシンプルなタマゴッチ風アプリはブラウザで完全に動作し、状態を `localStorage` に保存します。

## 遊び方 (How to Play)

ハンギョドンは可愛いペットのようなキャラクターで、毎日お世話をしてあげましょう！

### 基本ルール
- **お腹**: 毎分1ずつ減っていきます。0になると機嫌が悪くなります。
- **機嫌**: お腹が空いていると下がります。-100になるとゲームリセット！
- **睡眠**: 夜22時〜朝6時頃に寝てくれます。寝ている間はお腹は減りません。
- **レベル**: 経験値を貯めてレベルアップ！レベルアップで100円もらえます。

### アクション
- **ご飯をあげる**: お腹を満たして機嫌を上げます。所持品から選んであげてください。
- **散歩する**: お腹を10消費して、ランダムイベントが発生！
  - 良いイベント: お金拾う、アイテム拾う、経験値ゲット、気分アップ
  - 悪いイベント: お金落とす、アイテム落とす、気分ダウン
- **お風呂に入れる**: 気分を30上げます。一日一回だけ！
- **お金を稼ぐ**: 10秒間ボタンを連打して稼ぎます。10分に一回だけ！
- **全リセット**: ゲームを最初からやり直します。

### ショップ
- お金を使っておにぎりやパンを買えます。
- 買った食べ物は在庫に貯まって、ご飯をあげる時に使えます。

### 通知機能
- お腹が0になったら、LINEで一日一回通知が届きます（サーバー設定が必要）。
- ブラウザを閉じていてもスマホに届くので、忘れずにご飯をあげてね！

### 目標
- レベルを上げて強いハンギョドンに育てよう！
- 毎日お世話して、機嫌を良く保ちましょう。

## 24時間動作システム（改良版）

ブラウザを閉じていてもペットが生き続け、LINE通知が届く完全24時間動作バージョンです。

### 主な機能
- **SQLiteデータベース**: ペットの状態を永続的に保存、ユーザーごとに個別管理
- **サーバーサイド自動更新**: サーバーが毎分すべてのユーザーのペットを更新
  - **機嫌は1分ごとに-1**（寝ていない場合）
  - 空腹度が時間とともに自然に増加（1時間で約10%）
  - 睡眠スケジュールを24時間維持
- **クライアント-サーバー同期**: 双方向の状態同期
  - クライアント操作時にサーバーに状態を送信
  - 1分ごとサーバーから最新状態を取得（特にmood）
  - オフライン時でもローカル保存で動作
- **24時間LINE通知**: サーバーが自動的にLINE通知を送信
  - 空腹度が20以下になるとサーバーに通知
  - 1日1回のみLINE送信（重複防止）
  - ブラウザが閉じていても通知が届く

### 現在の動作状況
- ✅ **サーバー**: `http://localhost:3000` で24時間動作中
- ✅ **クライアント**: `http://localhost:3001` でアプリ利用可能
- ✅ **データベース**: `hangyodon.db` ファイルが作成済み
- ✅ **自動更新**: 毎分ペット状態を更新中

### クラウドデプロイ推奨
完全な24時間動作のため、サーバーをHeroku/Railway/Vercelなどのクラウドプラットフォームにデプロイすることをおすすめします。その際は：
1. `app.js` の `SERVER_URL` をデプロイ先URLに変更
2. 環境変数 `LINE_ACCESS_TOKEN` を設定
3. データベースはSQLiteのまま使用可能

## LINEプッシュ通知

ブラウザが閉じていても空腹通知を届けるため、[LINE Messaging API](https://developers.line.biz/en/services/messaging-api/) と小さなバックエンドサーバーを使用します。

### 通知仕様
- **トリガー**: 空腹度が20以下になるとサーバーに通知
- **送信頻度**: 1日1回のみLINE送信（重複防止）
- **動作環境**: ブラウザが閉じていても24時間動作

### バックエンドセットアップ

1. LINEボットチャンネルを作成し、**チャンネルアクセストークン** を取得します。（LINE通知を使わない場合は不要）
2. このワークスペースをクローンまたはコピーし、`npm install` を実行します（`sqlite3`を含む依存関係がインストールされます）。
3. トークンを設定してサーバーを起動します：
   ```bash
   $ export LINE_ACCESS_TOKEN="YOUR_TOKEN_HERE"
   $ node server.js
   ```
   またはWindows PowerShellの場合：
   ```powershell
   $env:LINE_ACCESS_TOKEN="YOUR_TOKEN_HERE"
   node server.js
   ```
   LINE通知を使わない場合は`LINE_ACCESS_TOKEN`なしで起動できます。
4. クライアント側の `app.js` で `SERVER_URL` をサーバーのアドレスに設定します（デフォルト：`http://localhost:3000`）。
5. クラウドデプロイの場合、`app.js` の `SERVER_URL` をデプロイ先URLに変更し、環境変数 `LINE_ACCESS_TOKEN` を設定します。

### フロントエンド統合

`app.js` にはサーバー同期機能が組み込まれています：

```js
// サーバーURL設定
const SERVER_URL = 'http://localhost:3000';
let userId = localStorage.getItem('hangyodon_userId') || 'user_' + Date.now();

// サーバーからペット状態を取得（1分ごと）
async function syncFromServer() {
  const response = await fetch(`${SERVER_URL}/api/pet/${userId}`);
  const serverPet = await response.json();
  hangyodon.mood = serverPet.mood;  // サーバー側で毎分-1される
  hangyodon.hunger = serverPet.hunger;
  // ... 他の状態も更新
}

// サーバーに空腹通知（空腹度20以下で1日1回）
function notifyServerHunger() {
  fetch(`${SERVER_URL}/api/hunger`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ userId: userId, hunger: hangyodon.hunger })
  });
}
```

**userId**: 各ユーザーを識別するID。`localStorage` に保存して同じ端末では同じユーザーとして扱われます。

### 注意事項

* **データベース**: このシステムはSQLiteを使用します。本番環境ではPostgreSQLなど本格的なDBを推奨します。
* **認証**: 現在、userIdはクライアント側で生成されています。本番環境はユーザー認証実装を検討してください。
* **LINE通知**: 環境変数 `LINE_ACCESS_TOKEN` がない場合、通知機能は無効になりますが、ゲームは正常に動作します。
* **CORS**: ローカル開発時にCORSエラーが出る場合、サーバーのCORS設定を確認してください。
* **24時間動作**: サーバーが動作している限り、ブラウザを閉じていてもペット状態が更新され続けます。
